# Decisions (one-line ADRs)

Full project decisions: `Docs/DECISIONS.md` and the decisions table in the upgrade plan (D1–D10).

- 2026-10-27 ADR-AI-1: Claude Code setup is project-scoped (`.mcp.json`, `.claude/`). One Unity MCP (CoplayDev MCP for Unity 10.0.0, HTTP 127.0.0.1:8080) plus the official Unity Agent Plugin skills.
- 2026-10-27 ADR-AI-2: Context7 runs on the free tier with no key, only when an API or version is uncertain.
- 2026-10-27 ADR-AI-3: Work goes on `claude/<feature>` branches from the current work branch. WBS commit prefixes are kept, and merges happen only on the user's approval.
- 2026-10-27 ADR-AI-4: `Logs/` stays readable, because it holds build and probe evidence. Library/Temp/Obj/Builds/UserSettings are denied to Read.
- 2026-10-27 ADR-AI-5: Skills are manual-only (`disable-model-invocation`), with Sonnet for routine work and Opus for architecture and debugging.
- 2026-10-27 ADR-AU-1: All game audio is synthesised in code (`RehabSoundBank`): six material families, variant pools, loudness targets with a −1 dBFS ceiling. No recordings, no new dependencies.
- 2026-10-27 ADR-AU-2: `GripRehabMixer` (Master, SFX, Ambience, Voice) is generated once by `RehabAudioMixerBuilder`, which calls Unity's editor `AudioMixerController` by reflection (there is no public API). The asset is committed; the runtime falls back to per-source volumes without it.
- 2026-10-27 ADR-AU-3: Impacts are detected in both `OnCollisionEnter` and `OnCollisionStay` (with a firmer threshold), from the fastest contact point, because a landing on a contact the engine kept alive sends no Enter.
- 2026-10-27 ADR-VO-1: Voice uses only Windows on-device keyword recognition (commands and NATO/letter spelling). Free dictation is not offered because Windows dictation is an online service; the user chose offline spelling (D9 revised).
- 2026-10-27 ADR-VO-2: The voice router is Unity-free and tested from transcripts; voice never produces grip force, losing-progress commands always need "confirm", and low-confidence results ask before acting.
- 2026-11-06 ADR-WBS-1: Game code lives in `Assets/Rehab/<WBS>`. The assembly layers `Product`, `ProductIntegration`, `UI`/`UIBridge` and `_Project/Core` span several WBS IDs, so they stay as layers rather than being split by WBS (the user's choice). `Docs/ai/PROJECT_MAP.md` § "WBS → code" is the index for them.
- 2026-11-18 ADR-TEA-1: Tea liquid is an in-house simulation on real relations (LiquidCore: frustum volume, Torricelli flow from the head of tea, the first sloshing mode of a cylindrical tank, rim spill, a stream that narrows as it falls), chosen by the user over Obi (paid) and SPH particles (slow, unstable at the perf target). Volume is conserved to the millilitre and tested offline. Held teapot and cup hang upright; the wrist roll tips them. Keyboard pouring brings the pot over the looked-at point; the camera hand carries it itself.
- 2026-11-18 ADR-TRACK-1: Camera-hand depth (palm size) is measured with x scaled by the image aspect, so a wrist roll does not move the hand in depth (found while testing the tea pour).
- 2026-11-19 ADR-TRACK-2: Camera-hand mapping is measured on a real hand (Hand Lab: a guided 2-minute session records landmark numbers only, never images, and `Tools/hand_replay.py` plays it back into the game). Depth is automatic: the hand keeps its screen place and sits just above what is under it (the user's choice over palm-size depth, whose noise was 6-8 % at rest); the grab takes the object under the hand first; the mapping is centred on the measured resting wrist (y 0.70 of a laptop webcam image); edge look needs a 0.5 s hold; the bridge holds a single hand's left/right label against short flips. Replay results are not a fair grab measure (the recorded path reacted to the old hand); the user's second live session is the judge.
- 2026-11-21 ADR-ASSIST-1: Movement assist (camera hand): a Bayesian intent predictor (`IntentAssist`, Unity-free) over the objects and the rule-accepted places of the current activity (`Activity.Allows`). It pulls the hand, finishes placements on the object itself, and lowers the grip threshold for the intended object. Levels: Off, Low, Medium (default), High. Every assisted grab or placement is reported apart from the patient's own reach. Tools (spoon, knife) still act on what the view looks at. Verified SYNTHETIC with the activity probe: camera full reach and intent mode (70 % reach with tremor). The phone camera over USB stays optional: about 610 ms delay MEASURED on the test phone (`Docs/PHONE_CAMERA.md`).
- 2026-11-21 ADR-DEPTH-1: Camera-hand depth is controlled by the hand (supersedes ADR-TRACK-2's automatic depth by default): the hand nearer the camera moves the virtual hand forward (up to 55 cm), farther moves it back (15 cm). Cue: palm size and image/world bone-length ratio averaged in log space, held while the hand travels across the image (`HandDepth`, Unity-free, 9 offline tests). On two real Hand Lab recordings it cut depth jitter about 3x (MEASURED landmarks replayed offline, `Tools/hand_depth_eval.py`); arm sweeps still change apparent size (single-camera limit). Settings: HAND DEPTH (CAMERA) / AUTOMATIC.
- 2026-11-21 ADR-ASSIST-2: Complex tool motions are automatic with the movement assist (Medium, High): the assist brings a held tool to its work (`Activity.ToolWork`: next cucumber cut, pan, tomato) and `Activity.AutoTool` cuts or stirs; the needed tool is the likely next item; items for the same open place are one equal choice (`IntentAssist` groups); the teapot spout is held over the cup while still tipped. Every assisted cut or stir is counted (`handling.autoToolActions`). Activity probe (SYNTHETIC): keyboard 14/14, camera 14/14, 70 % reach with tremor 14/14.
- 2026-11-21 ADR-TEA-2: Tremor windows count only while the hand holds (slow path under 10 mm, was 20): the start or end of a voluntary move read as 0.3-1.3 mm. SYNTHETIC: still hand 0.01 mm, injected 1.5 mm / 6 Hz read 1.57 mm / 6.00 Hz.
- 2026-11-21 ADR-PHONE-1: The phone camera is optional. Phone Link's connected camera ("Windows Virtual Camera", found by name) delivers 1280x720 at 30 fps (MEASURED); its delay is not measured yet. The USB path (scrcpy) measured about 610 ms and stays off by default. The laptop webcam remains the default.
- 2026-11-22 ADR-TRACK-3: Camera-hand orientation is absolute, seen from behind the hand (supersedes the relative reference): the pose points are already in the patient's frame, so fingers up with the palm toward the camera shows the back of the hand toward the eyes, thumb on the left for a right hand. The old reference was the pose the hand had when it first appeared (a hand that entered tilted stayed tilted), and the prefab limited turns to 55 degrees at 75 %. The camera hand now takes the measured orientation unlimited (a 180-degree limit path is ambiguous), smoothed frame to frame. Checked with `Tools/hand_pose_check.py` (SYNTHETIC poses, in-game screenshots) and offline tests (enters tilted, palm up 180 degrees).
- 2026-11-22 ADR-PHONE-2: Camo (Reincubate, free) is the default camera choice, the user's choice over Phone Link: 1920x1080 at 60 fps, tracker about 38 fps, screen-flip delay median 219 ms (MEASURED). The game starts Camo Studio, finds the camera by name and falls back to the laptop webcam without it. A black picture for 2 s (paused phone app) is reported in the game's prompt and clears when the picture returns.
- 2026-11-22 ADR-GRIP-1: Object-led hand. The held object goes where the tracked hand, the movement assist and the safety checks put it; the hand is then drawn so its grip anchor lies on the object's grip point (`ApartmentExperience.ApplyVisualShift`), and the contact solver closes the fingers onto the surface. The shift is drawn only (undone before tracking and around the object's own target), so it never feeds back. Before, the assist moved only the object (up to 50 cm, "floating"), the safety clamp stopped the object while the hand sank into a table, and the follow lag left a gap. Grab range follows the assist level: the palm or a fingertip within 6 / 10 / 15 cm (Low / Medium / High) of the surface; not touching (over 3 cm) counts as assisted. The activity probe records hold quality per run (finger penetration, pad gap, hand correction).
- 2026-11-22 ADR-MAP-1: The laptop webcam is the default camera again (the user's choice for the three standing goals) and runs its wide 1280x720 stream at 30 fps (asked as 1920x1080; MEASURED: asking 1280x720 gives 10 fps), with 640x480 as fallback. CALIBRATE HAND (30 s, once, saved; Settings, voice "calibrate hand", offered on the first camera session): the patient's own left/right, up/down range maps to the full view and their near/far sets the depth gains and resting size (`HandCalibration`, 15 offline tests). Without a calibration the measured defaults stay.
- 2026-11-22 ADR-GRIP-2: Natural holding with the camera hand. While holding, the tracked hand takes the held object's grip shape (curl, spread, thumb opposed; `FingerPoseDriver`), and each wrapping finger closes to its **first contact** along the closing path, up to the hand's own limit (`ContactGeometry.LimitAngle` steps the sweep: checking only the final angle let a finger pass a thin book and end behind it). Pinch grips ease the object off a finger that is still inside it (bounded 4 cm, 5 cm/s). The teapot and cup are drawn in the hand too; the tea reads `TrackedHandPosition`, never the drawn hand (reading the drawn hand made a loop). A grab whose intended object cannot be taken never takes a neighbour. Activity probe (SYNTHETIC, camera hand): book pads touching 100 % (pad gap 0.2 mm), meal 83 %, plate/box/serve 54-81 %, tea 48 %; knife still 0 % (pads 6 mm off; the keyboard hand touches it), an open point.
